tencha-conoha CONFIG_MODULES=n migration record
================================================

Basis
-----
Collected from the running tencha-conoha host before the migration:
- loaded modules and their modprobe dependency closure
- bound Virtio block/network devices
- mounted filesystems
- Incus bridge, veth, nftables, and Btrfs storage use

Policy
------
- Convert modules required by the current boot path and services to built-ins.
- Disable unused modules instead of building every former module into the kernel.
- KVM is not used.
- Incus uses Btrfs storage; nested Docker/Podman and TUN/TAP users are not used.
- Keep loaded Virtio console, balloon, and RNG support.

NixOS configuration adjustment
------------------------------
Removed boot.initrd.availableKernelModules entries for virtio_pci and virtio_blk,
and boot.kernelModules entry for wireguard, because these drivers are now built in.
Set boot.initrd.allowMissingModules=true because NixOS otherwise requires module
files for supported filesystems even when all required support is built in.
The kernel package installs lib/modules/<version>/modules.{order,builtin,builtin.modinfo}
and runs depmod because NixOS and systemd use the resulting indexes to recognize
built-in functionality even when loadable module support is disabled.
Incus' generic vhost_vsock module request is disabled because this host does not
run Incus VMs. Host-specific assertions verify required built-ins and verify that
MODULES and MODULE_SIG remain disabled.
